    按钮打开一扇门¶

    本案例使用项目已有的 按钮打开滑动门 组合。完成后，你能解释它的连线、另存自己的版本，再把它放进自己的关卡试玩。

    准备与预期结果¶

    • 已用 Godot 打开项目，并能打开 GodotLevelEditor 独立窗口。
    • 已有一个可以 F6 试玩的关卡；还没有时先完成 快速开始。
    • 案例素材：scenes/mechanisms/button_door.tscn 及同名 .graph.tres。

    最终效果：玩家靠近按钮按 F，按钮进入 pressed，滑动门开始打开，随后到达 open。按钮默认约 0.5 秒后弹起；此组合没有接关闭动作，因此按钮弹起后门仍保持打开。

    1. 先试玩已有案例¶

    在 Godot 文件系统中打开 scenes/levels/mechanism_whitebox_v1.tscn，按 F6。

    走到左侧按钮附近并按 F。观察按钮按下、门移动、门完全打开这几个不同阶段。这个测试关卡还有双压力板控制门和终端启动升降台两个组合。

    停止运行，继续下面的编辑步骤。案例关卡有自己的目标演示组件，普通新关卡不会自动出现这三项目标。

    2. 打开组合并另存为自己的版本¶

    1. 独立窗口点击 机关 → 我的机关。
    2. 找到 按钮打开滑动门，双击或点击 进入编辑。
    3. 点击 另存为，保存到 scenes/mechanisms/ 下一个未使用的名字，例如 wiki_button_door.tscn。
    4. 确认机关编辑页显示的是新路径，后续修改都在这份副本中进行。

    保存通过机关编辑器完成，它会成对保存场景和图定义。不要仅在文件管理器中复制一个 .tscn 后继续修改共用图资源。

    3. 读懂图里的四个节点¶

    节点 要检查的内容 在本例中的作用
    按钮组件 绑定按钮对象 提供真实按钮组件与状态
    滑动门组件 绑定门对象 提供真实门组件与状态
    进入指定状态时 绑定按钮；状态选 pressed 按钮进入按下状态时发出一次事件
    请求机关执行动作 绑定门；动作选 open 收到事件后请求门打开

    真正的事件连线是：

    按钮进入 pressed → 触发 → 请求门执行 open

    两个组件节点用来创建、绑定和配置空间组件，不需要把它们的布尔“值”输出直接连接到动作的事件输入。

    事件与状态不同

    pressed 是按钮当前所处的状态；“进入指定状态时”的输出是进入该状态那一刻发生的一次事件。端口类型需要一致，布尔值不能直接接事件输入。

    4. 重新连接这条线¶

    为了确认自己能配置逻辑，可以在副本中重连一次：

    1. 选中 进入指定状态时，在右侧绑定按钮对象，状态选择 已按下 · pressed。
    2. 选中 请求机关执行动作，在右侧绑定门对象，动作选择 open 对应的打开动作。
    3. 如果两者尚未连接，从前者的 触发［事件］ 拖到后者的 事件［事件］。若已有连线，可保留；无需再加重复连接。
    4. 点击 验证，处理实际报出的绑定或端口问题，然后点击 保存。

    如果从空白图制作，可点击 + 节点 搜索并添加上表的四类节点。添加组件后，触发和动作节点仍需要分别选择对应对象。

    5. 调整组件参数¶

    选中按钮组件，在右侧 组件状态配置 中检查初始状态、允许交互、锁定和单次使用。第一次测试保持按钮初始 idle、允许交互、未锁定。

    检测范围、按钮复位时长和门的动作时长等参数在原生检查器中调整。机关页的 定位三维对象 / 检查器编辑 可以跳到对应组件。

    本例的门关闭了直接玩家交互，让开门由按钮驱动。门的 closed → opening → open 是实际运动过程，不能把动画过渡状态随意设成初始状态。

    右侧 预览 / 停止 和 模拟交互 用于隔离检查；最终仍要在关卡里用真实角色验证。

    6. 放进自己的关卡¶

    1. 保存机关副本，回到自己的关卡场景与原生 3D 视口。
    2. 点击 呼出轮盘 → 机关 → 关卡常驻 → 已有素材，选择刚才另存的组合。也可从 Godot 文件系统将该场景拖进关卡。
    3. 把组合放在地面可达的位置。结束放置后检查按钮和门的位置、尺度及碰撞是否合适。
    4. 保存关卡，确认当前活动场景为这个关卡，按 F6。
    5. 走近按钮按 F，确认门实际打开并可以通行。

    预期结果：按钮、门和它们的连线作为同一个组合工作；无需先接取任务，也无需把任务执行器手动加入场景。

    7. 若要把开门作为任务目标¶

    开门动作的 已接受 输出表示指令被接受，门可能还在运动。要在门完全打开后完成任务，应在对应任务图中读取真实门状态：

    任务开始 → 等待机关到达状态：门 / open → 完成当前任务

    选择的是你当前关卡里那一个组合的门组件。同源素材放置多份时，要分清实例。等待节点启动时会先检查当前状态，门已打开则立即通过；opening 还不算 open。

    任务图仅在所属事件接取／启动且它是当前有效任务时执行。这一步属于扩展用法，完整接取规则见 常驻关卡图说明。

    完成检查¶

    • 副本路径与内置素材不同，场景和图定义都已保存。
    • 触发绑定按钮的 pressed，动作绑定门的 open。
    • 在自己的关卡中，靠近按钮按 F 能实际开门。
    • 重开关卡仍能使用，未覆盖原按钮开门素材。

    无法互动或门不移动时，查看 机关不响应。节点参数见 机关与节点速查。
