    专项资料与阶段记录

    本页保留模块说明、接口或阶段验证，可能同时包含历史条款。当前操作先看 Wiki 首页；功能边界以模块最新覆盖说明与实际实现为准。

    GodotLevelEditor：节点连线编辑工具共同规范¶

    2026-11-16 机关状态：新增七种通用机关素材与命名状态接口，机关图、任务图、常驻关卡图共用真实组件状态。交互成功、指令接受、实际动作完成分别表达；等待节点先检查当前状态。恢复状态不重放事件。机关显示名不带“白盒 ·”“示例 ·”等前缀。详见 机关接口 和 使用与验证。

    2026-11-15 导航统一：关卡、机关和 NPC 的一级入口先进入各自“我的…”目录，选择具体资源后进入编辑；新建也放在目录。套件托管原模块面板，继续复用其保存、撤销和运行组件；原生 3D 摆放、资源格式与用户内容保持。接口与验证见 套件合同。

    白盒转型覆盖说明 · 2026-11-12¶

    当前以个人白盒编辑器为目标。时间暂停、回溯／快进、录像分身、轨迹、能量和能力解锁已删除。此前时间线／分身操作要求仅为历史记录。四套编辑器、定义格式、稳定 ID、连线、组件交互及调试继续保留。组件 tl_capture/tl_restore 供状态保存、复位与编辑器操作使用，不再注册时间线；has_item 只使用角色道具接口，无接口时返回 false。主入口为空白工作区，不接入旧谜题、守卫或剧情。验证见 转型记录。

    更新：2026-11-02。本文记录制作方式与专项边界；各模块实现情况见对应 README 与验证记录。

    共同目标¶

    关卡、机关、敌人状态机均采用类似蓝图的节点与连线编辑。工具运行在 Godot 编辑器内，节点图与三维视口配合使用。三维视口编辑位置、尺寸、模型、检测区域、接驳点和巡逻路线；节点图编辑关系、条件、行为和流程。

    三类图的职责¶

    专项 图中表达的内容 示例
    关卡与世界 房间拓扑、入口出口连接、谜题目标、完成事件、世界解锁 房间完成事件 → 开启捷径 → 更新目标与保存进度
    机关 触发、状态、条件判断、动作与可复用组合 拉杆开关状态 → 与压力板状态做 AND → 门的目标开合状态
    敌人 状态、行为参数、有条件且带优先级的状态转换 巡逻 → 听到声响 → 调查 → 搜索结束 → 巡逻

    关卡专项分别提供房间连接图和事件逻辑图，两者使用明确的连接语义。房间连线不会自动生成走廊几何；对应接口在视口中对齐和连接。

    共同编辑体验¶

    • 通过搜索菜单添加节点；拖动节点端口建立或断开连接。
    • 支持缩放、平移、多选、复制、删除、撤销与重做；节点位置与画布视图可保存。
    • 选中节点可编辑参数，并在三维视口定位关联对象；选中场景对象也能定位对应节点。
    • 连线区分事件执行、数据值、状态转换、空间接口。端口有类型、名称、颜色和文字提示；颜色仅为辅助信息。
    • 首版数据类型以布尔值、数值和对象引用为主；布尔状态与一次触发事件明确区分，转换使用显式节点。
    • 每个图节点、端口和场景对象有稳定标识。重命名显示文字、重新排列节点不改变引用；复制对象分配新的实例标识。
    • 试玩时显示实际执行的事件、当前数值、活动状态及最近转换原因；编辑中的图与运行实例明确对应。
    • 保存或导出前检查缺失节点、无效端口、类型不匹配、悬空引用和没有明确推进规则的循环。

    技术与资源边界¶

    • 默认白盒与 3C Playground 共用 米制网格，使用 1 / 0.5 / 0.1 m 刻度；scripts/tools/metric_grid.gd 创建独立底色及状态副本。正式 visual_scene 自带材质，光照 V1 保持基线。

    • 使用 Godot GraphEdit / GraphNode 构建画布；画布交互、资源数据、运行执行器分别实现。

    • 图由预制行为和条件组合。新增攀爬、飞行等基础能力时，由相应运行组件提供实现，再暴露为可配置节点。
    • .tscn 保存场景结构、组件、空间布局及图资源引用；.tres 保存图的定义。两者分工互补，每项数据只维护一份来源。
    • 图的排版数据与运行语义分开保存；移动画布节点不会改变场景对象位置或执行顺序。
    • 定义资源带版本信息，运行实例独立维护状态，不修改共用定义。加载时校验；不静默覆盖不支持的资源版本。
    • 白盒版与正式版引用同一布局与逻辑。美术模型、材质和表现可以替换，经过验证的碰撞、触发器、接驳点和行为继续使用。
    • 总控负责共用规范及适合复用的画布组件；专项可以先完成独立模块，之后依据稳定接口集成。

    执行、回放与回溯¶

    • 可影响谜题结果的逻辑与现有固定物理帧系统协调；显示帧率和画布排版不决定结果。
    • 条件同时满足时明确优先级与稳定顺序。有限状态机每次事件最多一次转换；其他图明确事件处理预算与循环推进方式。
    • 连续数据连接与事件队列分别执行；需要记忆、延迟或反馈的循环使用有状态节点，避免同一帧无限传播。
    • 分身主动交互记录对象标识及动作信息，回放时检查对应交互条件；不能只依靠角色位置还原拉杆、攀爬等动作。
    • 快照覆盖活动状态、计时器、门的开合进度、待处理事件以及必要行为进度。还原时直接恢复状态，不重新执行扣能量、警报、奖励等入场副作用。
    • 房间内可回溯状态与世界持续进度分开。永久解锁、完成事件和奖励明确触发次数及保存策略。
    • 调试使用独立测试进度，退出试玩恢复编辑状态。

    专项边界与已有接口¶

    • 机关专项：对象组件、可复用机关图、交互区域、输入输出、预览与独立验证。
    • 敌人专项：状态图、条件与优先级、敌人定义、实例执行及状态调试。沿用现有 敌人接口约定，保留稳定状态 ID 与通用守卫接口。
    • 关卡与世界专项：场景摆放、房间连接图、目标事件图、组件实例绑定、白盒保存及世界组装；复用机关与敌人定义。
    • 总控：公共接口、跨模块整合、玩家/时间线/存档的协调和完整流程验收。
    • 跨模块改动记录接口需求与兼容影响；并行开发时协调文件归属，防止相互覆盖。仅保留当前工具链、共享运行组件与用户制作的内容。

    首版验收样例¶

    1. 机关图：通过连线组合拉杆、压力板和 AND 条件，实际控制门；修改连线确实改变运行结果。
    2. 敌人图：用现有守卫制作四状态图，可编辑条件与优先级，并观察运行状态及回溯恢复。
    3. 关卡图：配置房间完成事件，解锁中庭捷径，并写入独立测试存档；空间连接有对应入口出口。
    4. 三类图均支持保存、关闭、重新打开，节点、参数、连线和场景绑定保持有效。
    5. 整体样例可在同一世界内连续游玩；切换正式美术后，关键解法、碰撞和回溯仍有效。

    总控 3C 接口更新 · 2026-11-02¶

    共享玩家与会话已切换到 WASD/Shift/空格、Q/E 浏览后暂停、T 继续、R 固定录像分身、F 主动交互。允许回到分身生成前，已有录像不被改写。HUD 仅保留暂停按钮，能量玩法移除。组合的 can_interact/interact 与无副作用快照接口不变，玩家/分身实际接入交互记录及回放。具体合同和验证见 3C Playground。本次未修改编辑器实现或用户关卡与机关资源。

    总控相机接口更新 · 2026-11-12¶

    默认世界和 3C 测试场改为第三人称越肩透视镜头，鼠标自由观察、右键拉近、V 换肩、中键回正。get_yaw_radians()、目标绑定与 _apply() 继续兼容原调用；新增捕获/释放鼠标、输入开关与目标对齐接口。释放鼠标时受控玩家和会话暂停接收操作，相机视角不进入录像或回溯快照。关卡、机关、敌人图及其稳定 ID、交互和快照格式不变。具体接口及复查入口见 第三人称相机。

    台本与任务专项 · 2026-11-12¶

    新增“台本与任务”工作区；任务图复用现有 GraphEdit 与事件执行器，增加 NPC 互动、ShowDialog、台本完成触发、任务开始／完成节点。台本库和任务定义为 .tres，NPC 与场景绑定为 .tscn；任务永久进度接入现有存档，与房间回溯分开。公共接口与验证见 台本与任务。既有三套编辑器及资源格式继续兼容。

    统一窗口与配表 · 2026-11-12¶

    GodotLevelEditor 专项编辑器统一托管于独立系统窗口。图数据仍为原生 .tres，台本与事件任务配表统一 XLSX，目录为配表/。事件启动条件、任务稳定 ID、执行排序和图路径由事件工作簿保存；运行执行器按事件串行推进任务。分类只用颜色，移除类别前缀与空运行提示。接口和验证见 套件合同。

    GodotLevelEditor 导航与原生视口 · 2026-11-13¶

    项目品牌和内部命名同步改为 GodotLevelEditor；已有 UID、用户场景与图资源稳定 ID 保留。场景摆放只使用 Godot 原生 3D 视口，删除套件中的镜像视口。独立窗口以关卡、任务、机关、台本、NPC、其他六个矩形蓝色按钮导航，表格及各类图继续独立编辑；任务表／任务图归入任务入口。合同与回归验证见 套件接口。

    大世界仓库与任务关卡约束 · 2026-11-13¶

    关卡主入口改为大世界分类仓库，包含关卡、出生点、Layout 白盒、常驻 Room、机关、NPC，原有关卡图保留为子页。关卡场景归入 scenes/levels，配表 levels.xlsx 保存固定 ID 与名称。事件不绑定关卡，任务在 events.xlsx schema 2 中保存唯一 level_id；编辑器和运行执行器均按此隔离，跨关卡任务依旧串行。接口及验证见 套件合同。

    编辑器视觉更新 · 2026-11-13¶

    套件使用米白页头、中蓝／深蓝矩形导航、白色画布、灰色详情栏。关卡目录采用真实缩略图及金色至深蓝渐变卡片；关卡编辑继续使用原生视口和分类仓库。页面、导航、卡片的短时 UI Tween 仅改善编辑操作反馈，不修改游戏表现、数据或运行图语义。完整说明和验证见套件合同。

    编辑器视觉与方格画布 · 2026-11-15¶

    独立套件改为冷灰底、白色面板和蓝色强调，导航及目录卡片缩紧，窄窗口自动减少关卡列数。任务、机关、关卡与 NPC 图统一使用带边框的浅灰方格画布；节点正文为白色，保留职责分类色、端口类型色及实际运行高亮。仅编辑器显示与布局变化，不改图数据、稳定 ID、连线、吸附、撤销、保存或游戏表现。接口和验证见 套件合同 与 本次验证。

    同日导航层级调整：页头移除重复产品名；一级导航使用蓝底白字，二级页签使用蓝字和底部指示线，两层之间有分隔线。按钮映射及切换接口保持。headless 54 项、Metal 渲染 62 项通过，见 导航验证。

    箱庭关卡覆盖说明 · 2026-11-15¶

    当前关卡模型为“一份场景就是一个完整箱庭大关卡”。空间布局与实际通路直接在原生 3D 视口制作；关卡编辑移除房间接驳图及其操作入口，不要求把 Room 相互连线。任务流程、机关逻辑、NPC 状态图保持各自职责。新建 Room 使用 uses_topology=false，多个检测区不要求 start_room_id；旧 uses_topology=true 房间、接驳图及运行校验继续兼容，仅供已有资源使用。此说明覆盖上文历史的关卡接驳图制作要求。验证见 箱庭工作流。

    同日选中动效：一级菜单选中加粗，菜单底色／二级指示线／关卡卡片／图节点边缘加入 0.14～0.24 秒反馈；不改变位置、缩放、命中区域、图子控件或端口。连续操作取消旧动画，兼容天空一级菜单及同期关卡改造。headless 56 项、Metal 64 项和节点端口 139 项通过，见 选中动画验证。

    天空与关卡环境 · 2026-11-15¶

    天空预设独立存为 .tres，关卡根 sky_preset 保存唯一引用；关卡信息显示并编辑该绑定，不在 XLSX 复制参数。预览与运行使用私有 Environment，旧关卡及 V1/V2 源资源保留，云层高度不生成云海。公共接口与验证见 天空专项。天空不使用节点图，不改变现有任务、机关及 NPC 执行。

    通用任务节点 · 2026-11-15¶

    任务图新增通用穿着／背包／角色状态检查、变量、等待、并行与汇合、子目标、失败、检查点、子图等 33 种节点，并开放 16 种已有节点。当前事件执行器连接场景、角色数据和运行调试；节点参数、进度恢复、同关卡检查点与兼容边界见 通用任务节点。原有用户资源、配表和默认白盒入口保持。

    常驻关卡逻辑覆盖说明 · 2026-11-15¶

    关卡图作为整关常驻逻辑重新提供，不恢复房间空间接驳图。关卡编辑删除与轮盘重复的素材及已放置列表；新增独立 level_logic 资源，复用任务图的类型化端口、通用节点和异步执行器。常驻图不需要接取任务，任务图仅在事件接取／启动后执行；接取第一项任务后，按既定顺序自动接续其余任务。NPC 引用限当前关卡常驻对象，接受任务节点在备注区选择本关事件首项任务。详见 常驻图合同。

    新增内容分类父节点 · 2026-11-16¶

    今后通过轮盘、仓库拖放、侧栏、实例化或复制新增的 NPC、Room、机关和关卡白盒，分别放到场景根下对应的空 Node3D 父节点。首次创建，后续复用；既有物件不迁移。容器创建和实例添加使用同一次撤销；保持世界变换、稳定 ID、预制件内部引用及原有存档／任务作用域。运行读取只穿过管理容器，不把预制件内部组件提升为关卡对象。接口及检查见 关卡接口 与 自动分类验证。

    同日命名细化：四类管理父节点统一为 NPCs、Rooms、Mechanisms、Whitebox；分类 metadata、对象 ID 和运行作用域不变。已有带标记的管理容器按新名称同步更新，业务节点不改名。
