# 插件结构调整后的流程回归

日期：2026-11-17。依据当前源码、重构前备份和本轮实际执行结果，检查插件化后从创建作品到重新打开、试玩和更新插件的流程。

## 用户确认的工作流

关卡保存为 Godot 原生 `.tscn` 文件，继续使用场景树、3D 视口、保存和 F6。“我的关卡”作为浏览、搜索和打开这些文件的入口保留；“关卡编辑”提供当前场景的常驻逻辑。浏览器不另外存一套地图数据。该确认已同步根 AGENTS.md，并覆盖迁移时“只显示当前图、不提供浏览”的约定。

个人地图、任务、配表、NPC、机关和天空资源位于插件目录外。更新只替换 `addons/godot_level_editor/`，不覆盖个人作品。已删除的时间线、分身和能量玩法不恢复。

## 发现的问题与处理

| 编号 | 级别 | 复现与影响 | 修复 |
|---|---|---|---|
| STR-01 | P1 | 原生关卡另存为后，副本第一次保存仍使用原关卡 ID，任务索引没有新地图；打开的逻辑面板也可能保留旧图引用 | 在根节点 POST_SAVE、路径更新后分配并写入独立 ID 和三类图资源；延后刷新列表，重绑实际图引用；保留继承和原文件 |
| STR-02 | P1 | 另存为覆盖已登记目标时，索引会出现同一路径的重复行，导致校验失败 | 已登记目标保留其稳定关卡 ID，每个路径只有一行；新目标获得独立 ID |
| STR-03 | P1 | 内置机关在面板和原生保存时直接改写 addon 场景／图，插件更新会覆盖作者修改 | 默认保护 addon 写入；面板引导另存到个人目录；原生拒绝后保留草稿；开发生成器使用显式写入许可 |
| STR-04 | P1 | 内置 NPC 的保存会覆盖 addon 定义 | 面板引导保存个人副本，Store 默认拒绝 addon 目的地 |
| STR-05 | P1 | 生成个人 NPC 场景仍默认写入 addon | 默认改为 `content/scenes/npcs/`，拒绝写入插件目录 |
| STR-06 | P1 | 导入 NPC 模型、贴图与场景快照仍写入 addon | 个人导入输出到 `content/assets/characters/npc_imports/`；自动生成目录使用英文 |
| STR-07 | P2 | 修改 NPC 身高后生成场景，模型为 2.6 m，碰撞仍固定 1.7 m，缺少匹配实例体型 | 碰撞与实例 profile 按当前身高生成；这是本轮发现的既有功能缺陷，不单独认定由迁移引入 |
| STR-08 | P2 | 继承场景没有覆盖天空属性时，读取不到基类的天空预设 | 沿 SceneState 基类读取，保留显式 null 覆盖 |
| STR-09 | P2 | 天空页已打开时新保存／另存地图，引用关卡列表仍显示旧结果 | 保存后延迟刷新真实索引和引用，关卡信息显示实际天空资源 |
| STR-10 | P2 | HDRI 取消后立即重新导入，新的文件扫描可能被旧导入通知漏过，界面停在等待状态 | 延迟扫描并在空闲时重试，保留请求身份检查和总超时 |
| STR-11 | P2 | 原生保存没有触发原有鸟瞰缩略图服务；默认目录以外的地图也被旧目录限制过滤 | 原生保存登记后请求缩略图，支持所有已登记的插件外项目路径，headless 不覆盖已有图片 |
| STR-12 | P2 | 结构迁移移除了关卡浏览入口，与用户本轮确认的使用方式不符 | 恢复“我的关卡／关卡编辑”二级入口，浏览真实地图，保留原生新建继承和保存 |
| STR-13 | P1 | 个人 NPC 的模型定义已保存，但原生场景保存会把旧缓存中的内置模型引用重新覆盖回磁盘 | 原子保存后用 CACHE_MODE_REPLACE 同步既有规范资源引用；保存、替换插件后检查个人依赖仍在 |
| STR-14 | P2 | 机关图自动居中／恢复视图把未编辑的素材标为有修改，保存保护进而阻止切换素材 | 仅主动平移、缩放等用户操作记录视图修改；自动布局不制造草稿 |
| STR-15 | P2 | 机关个人另存后仍沿用旧标签状态或残留内置拒绝提示 | 保留已写入的个人场景／图，恢复原标签磁盘数据，再以独立原生标签打开个人版本 |
| STR-16 | P2 | 个人 NPC 复制样例后修改模型或身高，目录仍用原样例身高、动画数和封面 | 内置样例保留原来源展示；个人资源显示当前身高／状态数，并预览当前模型 |

未保存的新关卡点击图保存时，显示先执行原生另存为的明确提示，避免把空路径交给保存 API。

STR-01 的早期原始记录为 `STRUCTURE_SAVE_AS original=10 live=10 disk=10`，25 项中 2 项失败。修复后新副本的 live／disk ID 一致且不同于原图。机关问题分别在开发副本与插件空工程真实改写磁盘的基线中复现，两种工程各 2 项保护断言失败；NPC 基线 15 项通过、10 项失败；天空继承／引用基线 27 项中 2 项失败。失败断言数量不等于独立缺陷数。

## 证据边界

- 初始 69 个 `content/` 文件和 175 个内置素材文件的 SHA-256 核对一致。作者地图、配表、稳定对象 ID 和源素材没有批量修写。
- 部分 headless 原生保存基线出现 Godot dummy renderer 的缩略图读取错误，测试已改用关闭原生缩略图的保存 API；真实缩略图另用 Metal 检查。
- 未修复基线与本轮隔离工程退出时均有 Godot 的 `Plugin is not attached to debugger`／ObjectDB 清理提示，保留原始日志，不冒充本轮修复的问题，也不把它计为流程断言失败。
- 既有黄昏山居地图的四个带负号对象 ID 校验问题在迁移前已存在，不属于本轮结构回归；不擅自改写作者稳定 ID。本轮通用运行检查通过不等于所有作者关卡的全部内容均无问题。
- 13 个 GuardAI 行为样例与剧情交互 NPC 原本是不同组件。本轮 F6 剧情检查使用已有剧情交互组件，不声称所有行为样例都能直接接取任务。
- 天空 HDRI 的早期 Metal 关闭／重开检查出现过 Godot List.erase 诊断，尚未定位到插件功能故障；预设保存、引用、F6 和文件哈希检查通过，原始日志保留。畸形 EXR 输入的预期解码错误有独立标记。测试不宣称所有引擎日志均无诊断。
- 交互测试必须隔离焦点。多编辑器／游戏并发时，失去前台会按原设计停用游戏输入；F6 子进程不会仅因编辑器使用 headless 自动变成 headless。最终运行器明确设置子进程模式、串行执行并聚焦自己的游戏，不修改任务或机关运行逻辑来迎合探针。
- 新任务夹具的最后一次 Metal 渲染 F6 合成 F 接取仍未通过；同夹具双工程 headless 完整运行、旧 47 节点 F6 和实际渲染拖线分别通过。该渲染输入项保留为未完成稳定验收，未擅自等同于产品 bug 或写作通过。原始失败和详细边界见 [叙事专项记录](../../narrative_editor/structure_2026-11-17/validation.md)。
- 本轮本地验收平台为 macOS／Godot 4.7.1；没有重做 Windows／移动导出或 PCK 专项。
- 用户随后授权修复完成后发布 0.1.1；全部门禁通过后由总控提交、推送标签并核验 GitHub Release，专项聊天不独立发布。原工程窗口不用于破坏性测试。
