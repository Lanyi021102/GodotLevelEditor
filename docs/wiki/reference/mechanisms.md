# 机关与节点速查

当前素材库只提供双开门、单开门、压力板、按钮和升降台，均独立运行。新建门使用 2×3 单开门或 4×3 双开门，操作见 [查看和调整旋转门](../tutorials/rotating-door.md)。状态与动作选项取自实际绑定组件。

## 素材、状态和动作

在 **机关 → 我的机关** 打开素材；在编辑页 **另存为** 后制作自己的版本。

插件内置素材为只读。修改内置机关后点击 **保存** 会引导另存为个人版本，默认在 `content/scenes/mechanisms/`；场景与同名图成对保存。Godot 原生保存也会保护插件源文件，看到拒绝提示时草稿仍未保存，需要完成另存为。个人版本会出现在“我的机关”和轮盘中，更新插件不会替换它。

| 素材 | 内置状态 | 内置动作 ID | 源场景 |
|---|---|---|---|
| 按钮 | `idle`、`pressed` | `press`、`release` | `addons/godot_level_editor/scenes/mechanisms/button.tscn` |
| 压力板 | `released`、`pressed` | 无；由实际占位驱动 | `addons/godot_level_editor/scenes/mechanisms/pressure_plate.tscn` |
| 2×3 单开门 | `close`、`moving`、`open` | `open`、`close`、`toggle` | `addons/godot_level_editor/scenes/mechanisms/single_door.tscn` |
| 4×3 双开门 | `close`、`moving`、`open` | `open`、`close`、`toggle` | `addons/godot_level_editor/scenes/mechanisms/double_door.tscn` |
| 升降台 | `at_start`、`moving`、`at_end`、`stopped` | `move_to_end`、`move_to_start`、`toggle`、`stop` | `addons/godot_level_editor/scenes/mechanisms/lift_platform.tscn` |

默认按钮约 0.5 秒后弹起。门和升降台的碰撞随运动更新；升降台可以承载角色。

两种门使用固定门框与内侧铰链门扇，`close` 为 0°，`open` 为 90°，`moving` 覆盖开关过程。图中直接显示结构、三张状态卡与可编辑旋转曲线。旧组合、拉杆、终端与旧门素材已从库和新增节点搜索移除。现有关卡的必要旧数据保留为关卡内部数据。

## 保存、冲突提示与复制粘贴 {#save-and-copy}

机关编辑页的 **保存 / 另存为** 与 Godot 原生保存路径都按场景和同名图定义成对保存。遇到“磁盘文件已被其他编辑修改”或“未保存”提示时，以机关面板的结果和未保存状态为准，不要仅凭原生保存动作已结束判断成功。

磁盘冲突、无效图或写入失败时，应保留当前草稿与磁盘已有内容。先核对冲突来源；需要保留两份内容时，使用未占用路径 **另存为**。**重载**前会检查未保存状态，只有明确放弃草稿时才确认重载。缺失输入、失效绑定等问题应按验证提示检查，不应为了保存而批量删除用户节点。

复制粘贴使用**复制时**的节点参数、位置、所选节点之间的连线和绑定组件快照。复制后再修改或删除源节点，不会改变剪贴板内容；粘贴为新节点和独立组件引用，支持撤销重做。需要复制新的修改时重新执行复制。

## 自定义动作与按钮复位 {#custom-actions}

自定义规则使用“原状态 → 动作 → 新状态”。动作出现在下拉选项中，不表示任何状态下都能执行：当前状态没有匹配规则、且该动作没有对应内置行为时，请求应走**失败**并保留拒绝原因。例如按钮仅配置 `idle → interact → pressed` 时，已处于 `pressed` 再请求该自定义 `interact` 不算成功。

按钮通过自定义 `interact` 转换进入 `pressed` 时，同样使用 `reset_after` 计时；大于 0 时按设定秒数复位，为 0 时不自动复位。状态快照恢复沿用保存的剩余计时，不重新发出交互、状态变化或动作完成事件。

以上操作对应 2026-11-16 修复版本，模块专项与总控独立整合检查已通过；具体结果、早期失败记录和源码快照见 [本轮 QA 记录](../../qa/bugfix_2026-11-16/validation.md)。

## 机关图中的常用节点

| 节点 | 输入 / 输出 | 主要参数 | 用途 |
|---|---|---|---|
| 门框 · 2×3 / 4×3 | 输出门框对象 | 实际门规格与初始状态 | 固定框体，提供门扇安装对象 |
| 旋转门扇 | 门框对象 → 门扇对象 | 门组件绑定 | 表达单扇或双扇铰链结构 |
| 旋转动画 · 0° ↔ 90° | 事件、门扇 → 已接受 / 失败 / 动画到位 / 门状态 | 动作、时长、可编辑曲线 | 真实执行旋转，显示角度和播放位置 |
| close / moving / open 状态卡 | 门状态 → 布尔成立 / 进入事件 | 实际状态 | 持续显示当前状态，进入时只触发一次 |
| 按钮组件、压力板组件、升降台组件 | 输出布尔“值” | 对象绑定及组件配置 | 绑定实际三维组件 |
| 检测机关当前状态 | 输出布尔“值” | 对象、状态 | 查询现在是否处于某状态 |
| 进入指定状态时 | 输出事件“触发” | 对象、状态 | 进入该状态的瞬间触发 |
| 退出指定状态时 | 输出事件“触发” | 对象、状态 | 离开该状态的瞬间触发 |
| 机关状态变化时 | 输出事件“触发” | 对象、原状态 / 新状态 | 按条件监听变化 |
| 交互成功时 | 输出事件“触发” | 对象 | 只接收成功交互 |
| 请求机关执行动作 | 输入事件；输出“已接受 / 失败” | 对象、动作 | 请求打开、关闭或移动 |
| 请求机关改变状态 | 输入事件；输出“已接受 / 失败” | 对象、目标状态 | 通过受支持规则请求切换 |
| 机关动作完成时 | 输出事件“触发” | 对象、动作、成功过滤 | 动作真正完成或取消时响应 |
| 如果条件成立 | 输入事件与布尔条件；输出成立 / 不成立事件 | 条件来源 | 按当前条件分流 |
| AND / OR / NOT | 输入 / 输出布尔值 | 连线 | 组合多个持续条件 |
| 布尔上升沿 → 事件 | 输入布尔值；输出事件 | 连线 | 条件由假变真时触发一次 |

“值”是持续数据，“触发”是一次事件。直接把布尔输出连到事件输入会产生类型不匹配；使用显式转换节点或状态触发节点。

## 任务图与常驻关卡图中的机关节点

两个图共用机关状态变化、交互成功、动作完成、感应区进入／离开、状态检查、状态等待、动作请求、状态请求及属性设置。

与机关图只绑定组合内部组件不同，这里先选择**当前关卡中的机关实例 / 组件**，再选择其状态或动作。

**等待机关到达状态**启动时先检查当前状态，未到位则等待，可配置超时。动作请求继续端口仅表示指令被接受。需要判断开门完成时等待 `open`，需要判断升降台到终点时等待 `at_end`。

## 参数在哪里修改

| 参数 | 位置 |
|---|---|
| 初始状态、交互可用、锁定、单次使用、自定义状态及转换 | 机关页选中组件 → 右侧组件状态配置 |
| 检测半径、复位 / 释放延迟、碰撞层、占位数量 | 对应组件的原生检查器 |
| 动作时长、升降台目标偏移、开门角度 | 对应组件的原生检查器 |
| 单/双开门旋转时长、曲线与开关预览 | 旋转动画节点内及右侧参数栏 |
| 任务图中的实例、状态和动作 | 对应图节点右侧参数栏 |

!!! note "状态边界"
    压力板的按下状态由真实占位驱动。`opening`、`closing`、`moving` 等过渡状态不能作为任意请求的目标；请使用动作或可停留的目标状态。

## 独立运行

- 按钮按下并按设定时间弹起，不自动控制门或升降台。
- 压力板报告自身占位与释放状态。
- 门通过自身交互和内部旋转动画开关；升降台通过自身交互往返。
- 需要联动时，由你在关卡图或任务图中绑定具体实例；素材库不提供预连线的组合。
