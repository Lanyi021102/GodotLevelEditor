# 常见问题

先确认你编辑的资源路径和当前活动场景。很多问题来自在另一份素材或默认主入口中测试。

## 打开 Godot 时在加载插件阶段等待很久 {#plugin-startup}

此前启动会一次创建独立窗口的所有页面、扫描目录并加载封面。现在打开 Godot 时先准备原生三维工具、运行与调试接口和保存保护；独立窗口在点击顶部 **GodotLevelEditor** 或 **项目 → 工具 → 打开 GodotLevelEditor** 时建立，先显示工作台，访问分类后再初始化对应页。

首次访问某个分类仍可能短暂停顿，已打开的页面会继续复用。机关和 NPC 的目录元数据会保存到本机 `.godot/` 缓存；源资源没有变化时，下一次访问可直接恢复目录。修改素材后自动失效，缓存损坏时自动重建，也可用 **刷新** 强制重读。

不用为此删除 `.godot/`，否则还需要重新导入资源和生成缓存。升级后先保存工作，再重新打开工程一次。首次导入、恢复大型场景、显卡初始化等仍由 Godot 完成，不属于此次延后页面创建所消除的工作。

## 点击机关、关卡等分类时停顿 {#navigation-performance}

机关和 NPC 目录现在会复用已加载的卡片和封面，切换分类不再重新加载全部素材。关卡、机关与 NPC 的卡片和详情共用图片缓存；分类导航只更新实际改变的选中状态。

新增、保存、删除素材或收到文件变化通知后，目录会自动检查是否需要更新。隐藏的目录延后检查，在再次进入时显示最新内容；无关文件变化不会重建目录。返回目录保留搜索、有效选择和编辑草稿。如外部修改尚未显示，可点击 **刷新** 强制重读。

首次打开项目、实际资源变化、打开大型场景或首次生成资源预览仍需要加载。更新这版插件后，先保存当前内容，再重新打开项目一次，使新的目录通知连接完整生效。不要通过反复删除 `.godot/` 来处理切换停顿。

## 更新编辑器后弹出大量图片导入 {#image-import}

Godot 会扫描工程目录并导入新增或修改的图片；Git 的忽略规则不会阻止 Godot 导入。文档截图和生成网站不参与游戏运行，现在 `docs/.gdignore` 与网站构建自动生成的 `site/.gdignore` 会让 Godot 跳过这两份目录，截图和 Wiki 仍可正常使用。

角色贴图、素材封面和游戏图标仍需导入；未修改的资源会复用本机 `.godot/` 缓存。首次打开工程、新增素材或缓存被清除后仍可能出现导入进度。平时保留 `.godot/`，无需为更新脚本或界面删除缓存。

规则生效后，`docs/` 和 `site/` 不再显示在 Godot 文件系统面板中；文档可从工作台的 Wiki 入口、系统文件管理器或文本编辑器打开。

## Mac 上字体太小，或节点放大后模糊 {#display-scaling}

独立编辑窗口现在自动读取所在屏幕的系统缩放，统一调整字体、按钮和间距；移动到另一块屏幕时会更新。若在 Godot 编辑器设置中明确选择了显示缩放，套件优先使用该设置。字体按逻辑尺寸显示，Retina 不重复放大。

节点文字使用可缩放的 MSDF 字体。已有会话更新后，保存当前工作并重新打开项目以加载主题和字体。一级导航采用单色图标加文字，选中后同步变色。

关卡目录可按名称或 ID 搜索，缺少缩略图时显示白盒示意图。台本的 ID／姓名列按当前字体计算宽度，省略内容可悬停查看全文，也可在下方阅读选中对白。检查结果和实际截图见 [显示更新验证](../godot_level_editor_suite/display_refresh_2026-11-16/validation.md)。

## 找不到 GodotLevelEditor 入口 {#editor-entry}

使用 **项目 → 工具 → 打开 GodotLevelEditor**。如果菜单也没有，在项目设置的插件页检查项目所需插件是否启用，重点检查 `addons/godot_level_editor/modules/godot_level_editor_suite/plugin.cfg`；同时查看输出中的实际脚本错误。

首次导入需等待资源处理完成。已有会话遇到新插件或热更新后资源未刷新时，先保存，再重新打开项目。

## 在独立窗口找不到三维视口

三维编辑使用 Godot 原生 3D 视口。独立窗口提供关卡目录和逻辑编辑，不提供镜像视口。参见 [功能地图](features.md)。

## F5 没有打开正在编辑的关卡 {#f5-f6}

F5 使用项目主入口，目前进入默认空白工作区。打开你的完整关卡并让它成为活动场景，按 F6。

## F6 没有角色，或掉落后一直复位

先确认打开的是完整大世界关卡，而非单个普通机关或房间素材。完整关卡会自动接入角色、镜头和 HUD。

再检查玩家出生点是否位于有效地面上方、地面是否有碰撞，以及角色附近是否被物件包住。新关卡可从 [快速开始](getting-started.md) 建立对照。

## 呼出轮盘没有放下物件

轮盘先选择类别；NPC、Room、机关还需要选择常驻／任务范围。进入放置预览后，在地面左键确认。松开鼠标侧键不会自动选中素材。右键或 Esc 会结束放置。

## NPC、Room 或机关放下后不显示 {#task-object}

检查原生检查器中的 **存在范围 / 所属任务**。任务对象必须绑定当前关卡的任务，且仅在该任务 active 时显示、处理和碰撞。未选择任务或任务尚未激活时，关闭是预期行为。

用于常驻环境或负责接取任务的 NPC 应选 **关卡常驻**。同时检查实例的初始启用配置与有效模型场景。

## 按 F 没反应，或按钮按下后门不动 {#mechanism-response}

依次检查：

1. 游戏画面已获得焦点，玩家已靠近按钮的交互范围。
2. 按钮允许交互、未锁定；若开启单次使用，确认没有已经用过。
3. “进入指定状态时”绑定的是按钮，状态为 `pressed`。
4. “请求机关执行动作”绑定的是门，动作为 `open`。
5. 事件连线从触发端口到事件输入；已保存场景和图定义。
6. 测试关卡里放置的是你刚修改的机关版本。

最后在机关页点击 **验证**，按实际提示处理无效引用。可对照 [使用独立机关](tutorials/button-door.md)。

## 请求已接受，为什么门还没到位

“已接受”表示命令被接受，门仍可能处于 `opening`。需要实际完成时，使用动作完成事件，或在任务／常驻图 **等待机关到达状态** `open`。

## 原生保存后机关仍提示未保存

先看机关面板中的冲突或校验原因。机关保存需要同时保护场景和图定义，原生保存动作结束不能单独证明已写盘。保留当前草稿，核对磁盘修改或使用新路径另存；不要在未确认内容时重载。复制快照与自定义按钮行为见 [机关速查](reference/mechanisms.md#save-and-copy)。

## 打开第二个任务图 {#switch-task-graph}

在 **任务 → 事件与任务** 中点击另一行的 **编辑**。当前图已保存时会直接打开目标图；当前图有未保存修改时，会显示切换提示：

- **保存后打开**：保存当前图后切换。校验或写入失败时保留当前图，并显示失败原因。
- **放弃修改并打开**：丢弃当前图未保存的修改，再打开目标图。
- **取消**：继续编辑当前图。

重复点击当前任务的编辑入口会保留当前修改和撤销记录。任务图工具栏的 **文件 → 打开任务图** 也使用相同的未保存保护。切换后，任务 ID 与目标图同步；保存入口为左侧 **保存**（保存前会校验节点）。

## 任务图没有开始运行 {#task-start}

检查事件是否已经接取／启动、该任务是否为事件中的当前项，以及任务是否绑定当前运行关卡。后续任务不会提前执行。

当前直接 F6 的常驻关卡服务不会用工作簿自动开始条件绕过接取流程。推荐用常驻图的 **接受任务** 选择本关事件首项任务，接取后后续项自动接续。旧显式执行器仍有自己的启动条件合同。

## 接取任务的 NPC 不在下拉列表

常驻关卡图只绑定当前关卡里已放置的常驻 NPC，任务 NPC 和其他关卡 NPC 不列入该选项。先把接任务的 NPC 设置为关卡常驻。

## 任务图提示 NPC 不存在或引用失效 {#missing-npc}

核对节点中的 NPC 引用与当前任务所属关卡。删除或替换 NPC 后，需要把相应触发重新绑定到实际存在的 NPC，再校验保存。保存和运行前的绑定检查应指出失效目标，避免任务一直等待不存在的 NPC。

运行时若显示“无法开始任务：任务名 — NPC / Room 不存在…”，先修复列出的目标与绑定；该提示不会把其他合法任务一并禁用。

当前任务自己的任务 NPC 可以在未激活时隐藏，不应仅因隐藏而视为引用失效；引用了另一任务的专属对象则需要检查任务归属。切换到另一关卡时，原关卡任务继续按跨关卡暂停／续接规则处理，不要求把其他关卡的对象复制到当前场景。常驻关卡图只接受常驻 NPC 的限制保持。

本轮这两类兼容路径的验收状态见 [QA-06](../qa/bugfix_2026-11-16/validation.md)。

## 新台本如何首次保存，如何打开 XLSX {#dialogue-files}

1. 在台本页新建并编辑对白，点击 **保存对白**，选择可写的 `.xlsx` 目标。
2. 确认出现“已保存全部对白”且未保存状态清除；之后的 **保存对白** 写入这个路径。
3. 使用 **打开对白** 选择合法 XLSX。旧版 `.tres` 台本仍可读取并迁移，保存时选择 XLSX 目标。

打开错误文件或写入失败时，查看台本页的错误原因；当前台本与未保存修改会保留。当前有草稿时先保存，再切换台本。首次保存直接使用 **保存对白**；检查结果见 [QA-03 / QA-04](../qa/bugfix_2026-11-16/validation.md)。

## HDRI 导入中无法切换或保存天空预设 {#hdri-import}

导入期间，预设切换、新建、复制、还原、保存／另存为及绑定操作会暂时被禁用或拒绝，避免导入结果写入另一份草稿。“保存全部”在此期间也不会提前保存天空草稿。等待完成后继续操作；成功导入仍需保存预设，随后再绑定关卡。

可以继续调整同一草稿的其他参数，也可结束预览或关闭独立窗口。导入完成不会自动重开窗口或重新开始预览。

若文件无效、读取失败或导入未完成，查看错误提示，操作解除锁定后可选择其他文件重试。状态与失败恢复的验证见 [QA-09](../qa/bugfix_2026-11-16/validation.md)。

## 台本、任务和场景分别保存到哪里 {#save-data}

| 内容 | 保存位置 |
|---|---|
| 关卡空间和常驻逻辑 | `content/scenes/levels/` 中的关卡场景 |
| 关卡目录信息 | `content/tables/levels.xlsx` |
| 事件与任务信息 | `content/tables/events.xlsx` |
| 任务节点图 | 任务行 `graph_path` 指向的 `.tres`，默认在 `content/resources/task_graphs/` |
| 台本对白 | `content/tables/dialogues.xlsx` |
| 机关 | 对应 `.tscn` 和 `.graph.tres` |

使用独立窗口 **… → 保存全部** 保存多个编辑页的数据。Excel 中修改后先关闭文件，再在编辑器重新读取；避免两边同时保存不同草稿。当前运行器不读取旧 CSV 备份。

## 需要反馈问题时提供什么

记录编辑器版本、具体资源路径、操作步骤、实际结果和预期结果。若是节点问题，附节点绑定与连线截图；若是运行错误，保留输出中的第一条实际错误。这样可以直接定位到 [维护索引](development/index.md) 中的模块。

## 天空参数为什么有些不显示 {#sky-parameters}

天空页按“天空背景、时间与太阳、环境光、云层、雾”分类。按时刻计算时，实际角度显示在蓝底只读区域；需要改角度时切换“手动设置角度”，会沿用当前太阳位置。时刻可直接输入 `HH:MM`，颜色可输入十六进制色值，云量和雾浓度用百分比显示。

HDRI／光照模板使用素材自带的天空，程序配色和云层参数因此不显示；云层、雾关闭时也会收起对应参数。设置范围、预览和绑定步骤见 [天空指南](guides/sky.md)。


## 保存任务图时提示缺少所属任务 {#task-owner}

这表示“完成任务”等节点的所属任务 ID 缺失或无效。通过 **任务 → 事件与任务 → 对应任务行的编辑** 打开后，本图中的开始／完成／失败任务、NPC 互动和对话完成节点会自动关联当前任务；从其他任务复制节点也会重新关联。已有图在点击左侧 **保存** 时会再检查并补齐。

独立文件若已在事件表中唯一登记，也能按文件路径恢复所属任务。未登记或被多项任务共用的独立文件不会猜测任务归属；从任务表打开对应图，或为独立旧图填写有效任务 ID。错误现在显示具体节点名称及处理入口。
