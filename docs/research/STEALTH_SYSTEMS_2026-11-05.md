# 潜行、社会互动与多路径箱庭：调研及 GodotLevelEditor 设计建议

日期：2026-11-05。用途：为用户手工制作关卡提供系统依据。本文件是调研与设计建议，不是已实现功能清单。

## 1. 用户本轮提出的内容

| 关卡构想 | 关键体验 |
|---|---|
| 蒸汽朋克剧院 | 多种方式潜入；在演出高潮，于舞台中央取得秘密道具，再撤离 |
| 远古群居洞穴 | 无语言文字的关卡表达；观察图像、人物行动与环境，推断道具位置 |
| 赛博朋克政府大楼 | 使用高科技道具完成任务，留意强大敌人 |

NPC 不预设为敌人。玩家可以交涉、获得许可、伪装、偷窃、翻入或殴打抢夺；行为会影响后续世界状态。剧院入口已有四种想法：携梯伪装维修、偷取演出票、翻窗、殴打工作人员强行进入。NPC 交互通过玩家头顶气泡呈现，包含交涉、暴力与沉默等选择。

这些构想优先于此前文档中由 Agent 提议的钟楼、温室、码头案例。具体系统参数及玩法仍待白盒验证。

## 2. 调研范围与证据边界

本轮查阅官方功能介绍、官方游戏手册、开发者撰文和开发者直接访谈。没有重新实玩所有样本，也没有把社区猜测的数值当作事实。不同系列作品、模式和版本不能混用。

原作说明与“迁移到 GodotLevelEditor”的建议分开记录。后文的警戒分层、权限表、气泡交互和剧院方案均是本项目建议，不声称原作内部采用完全相同的数据结构。

## 3. 样本与可迁移内容

### 3.1 HITMAN：自由行动与社会空间

**查证内容：**IO Interactive 官方介绍强调伪装、工具、环境、操纵人物、窃听与机会发现，共同支持自由选择行动方式。Mette Podenphant Andersen 的 GDC 2019 讲座以社会空间解释《Hitman 2》的关卡设计。[官方功能介绍](https://ioi.dk/hitman/game-features)；[开发者讲座页面](https://www.gdcvault.com/play/1025879/Level-Design-Workshop-Hitman-Levels)。

**适合 GodotLevelEditor：**给每个区域定义用途与进入理由。剧院广场、观众厅、后台、舞台中央具有不同规则；拿着梯子、持有票券、接受剧务邀请分别提供不同的行动机会。通过 NPC 的工作和环境布局传达规则。

**边界：**讲座页面只能确认主题和摘要；本轮未取得完整幻灯片正文，不据此声称核实了该讲座的全部分类、当前 WOA 各模式的识破条件或警戒公式。

### 3.2 Deus Ex：交谈、战斗、技能是并行解法

**查证内容：**Eidos 官方《Deus Ex》介绍明确提供交谈、战斗和技能等解法。《Human Revolution — Director's Cut》官方手册分别说明中立/巡逻/怀疑/攻击状态，密码或黑客进入设备，黑客失败引发锁定和警报，以及通过对话说服特定角色。[系列初代官方介绍](https://www.eidosmontreal.com/games/deus-ex/)；[HR Director's Cut 官方手册，PDF 第 5、8–9 页](https://shared.fastly.steamstatic.com/store_item_assets/steam/apps/238010/manuals/DXHR-DC_PC_MAN_EN.pdf)。

**适合 GodotLevelEditor：**将“交涉成功”“取得权限”“从其他入口绕过”“强行突破”做成几条真实可用的路。赛博关的工具分别作用于门禁、传感器、信息或人员，而不是每扇门都要求同一种小游戏。

**边界：**本条明确区分初代与 HR，未用这些规则代替《Mankind Divided》最终版的具体实现。

### 3.3 Mark of the Ninja：可读的感知与调查

**查证内容：**参与开发的 Brook Miles 在 Game AI Pro 章节中说明，NPC 不仅需要发现玩家，还要感知噪声、异常和倒下的同伴，形成调查目标；Nels Anderson 的设计规则说明强调可理解的视听反馈与有限的失败代价。[开发者技术章节](https://www.gameaipro.com/GameAIPro/GameAIPro_Chapter32_How_to_Catch_a_Ninja_NPC_Awareness_in_a_2D_Stealth_Platformer.pdf)；[主设计师设计规则说明](https://www.gamedeveloper.com/design/-i-mark-of-the-ninja-i-s-five-stealth-design-rules)。

**适合 GodotLevelEditor：**NPC 先查看听见声音的位置，再决定下一步；玩家可以知道它正在调查什么。用转头、问号、短气泡、搜索位置和声音范围支持计划，而不是只在失败后宣布被发现。

**边界：**横版游戏的尺度和可见性规则不能直接套到俯视三维场景；GodotLevelEditor 需要自己验证遮挡、高差与提示拥挤问题。

### 3.4 Invisible, Inc.：把安全升级变成具体事件

**查证内容：**设计师 James Lantz 的自述说明，安全等级既受部分玩家行为影响，也会随回合推进；升级可提高防火墙或带来巡逻。他同时承认持续时间压力让部分玩家感到不公平，并说明提高反馈可预测性的过程。[开发者原文](https://www.gamedeveloper.com/design/game-design-deep-dive-alarm-systems-in-klei-s-i-invisible-inc-i-)。

**适合 GodotLevelEditor：**警戒变化带来可见的世界反应，例如加强验票、派人检查窗口、增加一道后台岗哨。

**需要调整：**GodotLevelEditor 的轻松探索适合先用事件触发升级，不直接采用“站着观察也不断升级”的回合计时压力。

### 3.5 Dishonored：长期世界反应与即时警报分开

**查证内容：**Harvey Smith 在 2012 年直接访谈中描述，玩家暴力行为和部分任务选择会影响后续人物对话、场景状况和结局分支。[开发者访谈](https://attackofthefanboy.com/e3/dishonored-developer-harvey-smith-talks-chaos-system-immersive-world-dunwall/)。

**适合 GodotLevelEditor：**剧院发生骚乱后，工作人员可能取消帮助、改变工作位置或加强后台检查；这些后果可以持续到撤离，而不等同于每个 NPC 一直追赶主角。

**边界：**来源是发售前设计访谈，适合说明设计意图，不用来确认最终版分数、杀人数阈值或续作公式。GodotLevelEditor 暂不需要覆盖所有时间线的单一善恶数值。

### 3.6 Chants of Sennaar：通过生活情境验证推断

**查证内容：**Rundisc 的 Julien Moya 在访谈中说明，语言理解来自观察人物与生活情境；重要信息在不同情境重复出现，让玩家验证假设，困难处通过补充情境线索调整。[开发者直接访谈](https://www.gamedeveloper.com/design/immersing-players-in-the-culture-of-a-people-with-language-puzzler-chants-of-sennaar)。

**适合 GodotLevelEditor：**洞穴关可以用壁画、携物路线、食物交换和仪式动作表达线索。同一信息至少有两种相互支持的呈现，玩家能用行动验证猜测。

**边界：**原作有可解读语言；借鉴的是情境推断方法。GodotLevelEditor 的洞穴时间线是否完全没有口语，属于虚构设定，不据此推断真实远古人类没有语言。

### 3.7 Oxenfree：贴着角色的对话与沉默

**查证内容：**Adam Hines 与 Sean Krankel 的直接访谈介绍贴着角色的气泡和连续对话。Netflix 官方支持说明，忽略提示可能形成沉默或默认回应，并影响互动。[开发者访谈](https://www.gamedeveloper.com/design/how-i-oxenfree-i-s-narrative-unfolds-like-a-free-flowing-conversation)；[官方沉默说明](https://games-netflix.helpshift.com/hc/en/31-oxenfree/faq/1201-what-happens-if-i-ignore-a-conversation-prompt/)。

**适合 GodotLevelEditor：**保留玩家头顶选项气泡，让回应发生在箱庭场景里；沉默、离开、展示物品都可以成为有语义的选择。

**边界：**这是交互呈现参考，原作不是潜行警戒系统模板；不能据此认定它具备 GodotLevelEditor 所需的攻击、权限与举报机制。

## 4. 建议的共同系统：四件事分别判断

以下全部为 GodotLevelEditor 设计建议。

| 判断 | 需要回答的问题 | 剧院例子 |
|---|---|---|
| 身份与许可 | 你被谁认可？允许去哪、做什么？ | 观众可以进厅，维修人员可以进入部分设备区 |
| NPC 当前认知 | 这个人实际看见、听见、相信了什么？ | 售票员看见推搡；后台守卫暂时只听说门口有骚动 |
| 区域安保 | 消息传到什么范围，工作人员如何响应？ | 加强验票、检查侧门、重新安排巡逻 |
| 持续世界后果 | 危机结束后有什么继续改变？ | 受伤职员离岗、帮助机会消失、演出暂停后需恢复 |

“真正获得许可”“被人当作有许可”“物品如何取得”也要区分。偷来的票可能通过普通验票，但盗票本身仍可能被目击或失主发现；观众身份不授权拿走舞台上的物品。帮忙维修而获准进入，才是另一种来源。

### 4.1 NPC 状态与关系分开

首版建议状态为：日常 → 注意 → 询问/劝离 → 调查 → 通报/搜索；是否追捕或攻击取决于角色职责、证据和威胁。普通职员可能退开求助，守卫可能拦截，机器人可能执行封锁。

沉默本身不是通用犯罪。验票时沉默可能被拒绝入场；洞穴里安静观察可能完全正常；政府大楼的身份核验可以要求回应。要让情境决定反应。

### 4.2 信息通过渠道传播

```text
行为发生 → 有人看见/听见/发现痕迹 → 形成具体信息
                                      ↓
                      当面告知 / 跑去报告 / 对讲机 / 监控网络
                                      ↓
                      接收者调查、检查或搜索 → 区域安保变化
```

无人发现的殴打不立即让全剧院认出主角；倒地人员后来被发现，可以提高安保，但未必知道施暴者是谁。看到施暴者的目击者、知道有人受伤的守卫、只听见响声的观众，掌握的信息不同。

三个时代可复用同一事件流程，改变传播渠道：洞穴靠视听和跑动传话，剧院靠工作人员与内部联络，政府大楼靠联网设备。通信中断不应成为无代价清空一切后果的按钮。

### 4.3 警戒升级先改变布置

首轮只验证三档区域安保：

| 状态 | 世界反应 | 仍然可玩的办法 |
|---|---|---|
| 正常营业 | 正常验票、巡逻与演出 | 探索所有入口 |
| 加强检查 | 检票更仔细、派人去异常位置 | 补许可、绕开调查者、制造其他机会 |
| 搜索封锁 | 守住关键出入口，调整巡逻 | 使用未被封闭的物理路线、恢复秩序或回退 |

不靠反复翻同一扇窗无限叠加难度。一次事件有唯一记录；重复观察不重复加分。暂时搜索可以结束，现场人员受伤、身份被识破等具体事实不会因短暂躲藏自动消失。

暴力需要有真实即时收益，例如立即突破门口，同时带来符合证据的风险。保留高警戒完成路线，避免用软锁强迫玩家重开或放弃自己选的玩法。

## 5. 剧院：进入方式与高潮取物是两个问题

### 5.1 大门附近的四条路径

| 用户的进入思路 | 先取得的机会 | 限制与后续选择 | 可能留下的后果 |
|---|---|---|---|
| 拿梯子装维修人员 | 携带符合工作的物件，提出维修理由，进入服务路线 | 负责人可能要求工单或指出待修地点；许可不覆盖所有后台 | 说辞不符时被询问；可通过实际帮忙获得信任 |
| 偷取演出票 | 以观众身份进入观众厅 | 需要继续寻找上台机会，如参与表演；票不是后台通行证 | 被目击盗票或失主报失后，相关人员加强检查 |
| 翻窗 | 绕过门口，抵达某个侧厅或走道 | 仍需处理路线、声响和被看见后的解释 | 窗口痕迹或噪音引发局部调查 |
| 殴打工作人员 | 快速突破阻拦并获得位置优势 | 惊动范围取决于目击与声音；之后需应对搜索或封锁 | 职员离岗、消息传播、后续许可更难取得 |

还可留一条真正获准的方式，例如帮助维修后得到负责人邀请。其成本是观察、找物和完成工作，而非暴力风险。

### 5.2 多种方式完成同一个舞台目标

用户指定的取物位置与时机保持为核心约束：**演出高潮时，舞台中央。**建议提供几种取得“合理行动机会”的办法：

- 观众路线：了解表演流程，争取成为上台的志愿者，利用正式环节接近道具。
- 维修路线：通过设备区操作升降台或布景，在高潮段落获得接近中央的机会。
- 隐入路线：由侧窗抵达吊顶或侧台，借布景遮挡进入目标位置。
- 强闯路线：以更高安保为代价抵达后台，再利用分身与机关创造取物窗口。

观众看见主角并不自动代表被识破。如果它符合当前表演情境，观众可以认为那是演出的一部分；剧务和安保可能采用不同判断。这样“潜行”也能发生在聚光灯下。

### 5.3 演出时间与回溯

白盒可先用“准备—演出—高潮—谢幕”四阶段验证，让灯光、音乐占位与演员动作传达阶段。首轮探索期不启动不可恢复的演出倒计时。

高潮要能通过排练、返场或重启演出再次触发。若玩家造成停演，给出恢复演出的可行办法，或明确提供重试；不能在保留唯一高潮目标时，悄悄让它永远消失。各种取得机会仍应在玩家理解的演出规则中发生。

## 6. 洞穴与政府大楼：复用规则，改变信息来源

### 洞穴

建议把“道具在哪里”做成可验证的证据链：壁画显示携带特殊物件的人进入高处洞口；日常活动显示食物送往同一方向；仪式中再次出现该物件的形状。玩家可以通过跟随、观察或交换取得进一步接近的机会。

这三个线索是本关建议，不是原作的固定配方。核心信息至少在两个不同情境出现；关键内容不能只靠一次极短动画或难辨颜色。气泡可以显示递物、指向、等待、拒绝、威胁等动作图像，并保留供玩家识别的操作提示，不提前翻译出答案。

### 政府大楼

建议先提供两种用途清楚的科技工具，例如临时凭证与信号诱饵；之后再考虑 EMP。凭证影响门禁认可，诱饵影响设备/人员调查。EMP 能停设备，但异常断电也可能引来检修或安保。

强敌先在察觉、装备或追捕方式上有一项明确优势，同时保留可观察的限制，如固定检修时段、有限覆盖区或通信依赖。工具应提供有代价的机会；不把“强大”做成全图实时知道主角位置。

## 7. 玩家头顶气泡交互

保留用户提出的场景内气泡。首轮可用如下两层结构减少误触：

```text
选定 NPC 并显示目标描边
        ↓
玩家头顶：[交涉] [展示/递交物品] [沉默/离开]
另有明确的“行动”入口 → [推开/殴打]，按住确认
```

具体显示哪些项由情境决定，不要求每个 NPC 永远列出同一整套菜单。攻击仍是玩家可以主动选择的世界动作；二级入口只是避免把普通交谈误点成暴力。

- 交涉可提供请求、说明身份、提出交换等短选项；白盒优先使用可检查的事实和道具条件，而非所有 NPC 都有长对话树。
- 沉默是明确回应，离开是结束互动，两者的后果可以不同。
- 先锁定目标再显示选项，避免旁人经过使攻击对象改变。
- 首版建议打开选项时暂停整个关卡，包括巡逻、演出和相关计时；不只冻结对话对象。确认后执行和继续。是否改为实时对话可后测。
- 头顶气泡用于选择；NPC 头顶问号、短回应和区域内安保变化用于反馈，避免只显示玩家选项却不解释结果。

## 8. 时间与分身对社会系统的约束

这些是待实现建议。当前运行合同仍以 [3C Playground](../3cplayground/README.md) 为准。

- 回退到施暴前，应恢复目击认知、伤害、传播中的报告、安保状态、权限变化和演出阶段；不能只把人物位置回退却继续保留未来举报。
- 同一次施暴或报告的重播不能叠加成多个安保升级事件。时间快照需要保存处理状态与队列。
- 固定分身若回放暴力、偷窃或交涉，必须记录稳定的对象与所选动作，并重新检查目标状态。首版可以先让分身只承担现有移动/机关动作，再逐项扩展社会动作。
- NPC 看到分身是否怀疑、是否把分身认作同一身份，需要统一规则和明确反馈；不默认所有时代人物都能识破时间能力。
- 关卡内部因果可回溯，撤离时才提交长期世界后果；不同时间线之间的连带影响须有剧情或传播依据。

## 9. 手工制作入口与现有缺口

现有工程提供巡逻、怀疑、警戒、搜索模板，噪音/求援入口、稳定状态 ID 与快照接口。它们是基础，不代表已具备中立 NPC、社会许可、对话、暴力伤害、证据传播和区域安保系统。复核位置：[敌人接口](../enemy_editor/INTERFACES.md)、`scripts/stealth/guard_ai.gd`、`addons/enemy_editor/runtime/enemy_machine.gd`。

| 用户需要编辑的内容 | 建议编辑方式 |
|---|---|
| 区域边界、入口与窗口 | 三维视口摆放和调整 |
| 观众/维修/安保可去哪、做什么 | 区域与身份的可编辑配置 |
| 人物岗位、巡逻、举报去向 | NPC 检查器与状态节点图 |
| 携梯、持票、工单等条件 | 交互条件节点与参数 |
| 目击后如何传播、何时加强安保 | 世界事件图与可配置消息渠道 |
| 演出阶段与舞台机关 | 事件图，关联灯光/门/布景组件 |
| 气泡选项、所需物品和回应 | 可复用交互配置；新增编辑入口待提供 |

这些编辑入口的新增部分均为需求，尚未实现。Agent 应补基础能力，用户摆放和组合内容；公共接口变更由总控协调，不在本次调研中直接改写专项执行器。

## 10. 推荐的首个白盒与验收

先做“剧院广场—门厅—一段后台—舞台中央—撤离口”的小片段，验证四种入口方案；先放三类 NPC（观众、职员、守卫）、三档区域安保、一件目标和一段可再次触发的高潮。

优先验证：

1. 四种进入方式分别通关，入口之后各有可理解的限制和机会。
2. 观众票不会直接开放后台；维修道具不会让所有人都认可身份。
3. 未被发现的行为不使所有人立刻识别主角；物证被发现后有合理响应。
4. 举报到达前后，相关区域的反馈与难度确实不同。
5. 高警戒仍有完成或恢复演出的办法，不发生无提示软锁。
6. 气泡沉默、离开与殴打区别明确，选错目标和误触暴力可被避免。
7. 回退到事件之前能完整撤销社会后果；固定录像重播不重复计数。
8. 用户手动修改许可、巡逻与演出事件，保存重开后仍能验证上述行为。

记录玩家能否说明“为什么被阻止、谁知道了什么、接下来还能做什么”，以及是否愿意尝试另一条路。首轮不必制作三个时代的全部美术或完整高科技战斗系统。
