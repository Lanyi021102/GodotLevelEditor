# Branch 双机协作

两台电脑各自保留本地工程，通过 Git 提交与 GitHub 仓库交换版本。两端统一使用 Godot 4.7.1。

## 第一次使用 Windows

1. 安装 GitHub Desktop，登录拥有仓库访问权限的 GitHub 账号。
2. 将 `Lanyi021102/branch` 克隆到普通本地目录，例如 `D:\Projects\branch`。避免放入 OneDrive 等自动同步目录。
3. 在 Godot 项目管理器中导入该目录的 `project.godot`，等待资源导入完成。
4. F5 运行默认场景；检查三套编辑器、角色、材质和输入。现有 `启动项目.command` 供 macOS 使用，Windows 直接从 Godot 打开工程。

## 每次换电脑

1. 开工前在 GitHub Desktop 中 Fetch，再 Pull。确认没有未处理的本地修改后打开 Godot。
2. 完成一项工作后保存工程，在 Changes 中检查文件，填写清晰说明并 Commit。
3. 换电脑前执行 Push，确认远端已收到提交。
4. 另一台电脑 Pull 后继续同一分支。未上传的本地提交不会出现在另一台电脑上。

`main` 保持可运行。较大的改动使用 `feature/任务名称` 或 `fix/问题名称` 分支，验证后合并。分支按任务划分。

## 文件与协作规则

- 提交场景、脚本、`.uid`、资源旁的 `.import`、插件、源模型、动画、贴图及许可文件。
- 机关 `.tscn` 与对应 `.graph.tres` 成对提交；关卡资源与其图定义引用一起检查。
- `.godot/`、日志、临时测试文件和导出产物由忽略规则排除。两端自行生成缓存。
- `.gitattributes` 已统一文本换行。新增资源路径的大小写应与引用一致。
- 同一场景或蓝图尽量由一方集中编辑。多人或多个聊天并行工作时，先约定文件归属；公共变更记录接口、兼容影响和验证结果。
- 三套编辑器、可编辑 HUD、用户制作的资源和光照 V1 按 `AGENTS.md` 保留。
- 模型等二进制文件发生冲突时，先保留双方副本，再选择或重新制作；场景合并后重新打开并试玩。
- Git 管理开发工程；`user://` 下的个人游玩进度由本机保存。
