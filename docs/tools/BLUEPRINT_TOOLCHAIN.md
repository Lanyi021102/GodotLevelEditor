## 共同目标

关卡、机关、敌人状态机均采用类似蓝图的节点与连线编辑。工具运行在 Godot 编辑器内，节点图与三维视口配合使用。三维视口编辑位置、尺寸、模型、检测区域、接驳点和巡逻路线；节点图编辑关系、条件、行为和流程。

## 三类图的职责

| 专项 | 图中表达的内容 | 示例 |
|---|---|---|
| 关卡与世界 | 房间拓扑、入口出口连接、谜题目标、完成事件、世界解锁 | 房间完成事件 → 开启捷径 → 更新目标与保存进度 |
| 机关 | 触发、状态、条件判断、动作与可复用组合 | 拉杆开关状态 → 与压力板状态做 AND → 门的目标开合状态 |
| 敌人 | 状态、行为参数、有条件且带优先级的状态转换 | 巡逻 → 听到声响 → 调查 → 搜索结束 → 巡逻 |

关卡专项分别提供房间连接图和事件逻辑图，两者使用明确的连接语义。房间连线不会自动生成走廊几何；对应接口在视口中对齐和连接。

## 共同编辑体验

- 通过搜索菜单添加节点；拖动节点端口建立或断开连接。
- 支持缩放、平移、多选、复制、删除、撤销与重做；节点位置与画布视图可保存。
- 选中节点可编辑参数，并在三维视口定位关联对象；选中场景对象也能定位对应节点。
- 连线区分事件执行、数据值、状态转换、空间接口。端口有类型、名称、颜色和文字提示；颜色仅为辅助信息。
- 首版数据类型以布尔值、数值和对象引用为主；布尔状态与一次触发事件明确区分，转换使用显式节点。
- 每个图节点、端口和场景对象有稳定标识。重命名显示文字、重新排列节点不改变引用；复制对象分配新的实例标识。
- 试玩时显示实际执行的事件、当前数值、活动状态及最近转换原因；编辑中的图与运行实例明确对应。
- 保存或导出前检查缺失节点、无效端口、类型不匹配、悬空引用和没有明确推进规则的循环。

## 技术与资源边界

- 默认白盒与 3C Playground 共用 [米制网格](../whitebox_grid/README.md)，使用 1 / 0.5 / 0.1 m 刻度；`scripts/tools/metric_grid.gd` 创建独立底色及状态副本。正式 `visual_scene` 自带材质，光照 V1 保持基线。

- 使用 Godot `GraphEdit` / `GraphNode` 构建画布；画布交互、资源数据、运行执行器分别实现。
- 图由预制行为和条件组合。新增攀爬、飞行等基础能力时，由相应运行组件提供实现，再暴露为可配置节点。
- `.tscn` 保存场景结构、组件、空间布局及图资源引用；`.tres` 保存图的定义。两者分工互补，每项数据只维护一份来源。
- 图的排版数据与运行语义分开保存；移动画布节点不会改变场景对象位置或执行顺序。
- 定义资源带版本信息，运行实例独立维护状态，不修改共用定义。加载时校验；不静默覆盖不支持的资源版本。
- 白盒版与正式版引用同一布局与逻辑。美术模型、材质和表现可以替换，经过验证的碰撞、触发器、接驳点和行为继续使用。
- 总控负责共用规范及适合复用的画布组件；专项可以先完成独立模块，之后依据稳定接口集成。

## 执行、回放与回溯

- 可影响谜题结果的逻辑与现有固定物理帧系统协调；显示帧率和画布排版不决定结果。
- 条件同时满足时明确优先级与稳定顺序。有限状态机每次事件最多一次转换；其他图明确事件处理预算与循环推进方式。
- 连续数据连接与事件队列分别执行；需要记忆、延迟或反馈的循环使用有状态节点，避免同一帧无限传播。
- 分身主动交互记录对象标识及动作信息，回放时检查对应交互条件；不能只依靠角色位置还原拉杆、攀爬等动作。
- 快照覆盖活动状态、计时器、门的开合进度、待处理事件以及必要行为进度。还原时直接恢复状态，不重新执行扣能量、警报、奖励等入场副作用。
- 房间内可回溯状态与世界持续进度分开。永久解锁、完成事件和奖励明确触发次数及保存策略。
- 调试使用独立测试进度，退出试玩恢复编辑状态。

## 专项边界与已有接口

- **机关专项**：对象组件、可复用机关图、交互区域、输入输出、预览与独立验证。
- **敌人专项**：状态图、条件与优先级、敌人定义、实例执行及状态调试。沿用现有 [敌人接口约定](../enemy_editor/INTERFACES.md)，保留稳定状态 ID 与通用守卫接口。
- **关卡与世界专项**：场景摆放、房间连接图、目标事件图、组件实例绑定、白盒保存及世界组装；复用机关与敌人定义。
- **总控**：公共接口、跨模块整合、玩家/时间线/存档的协调和完整流程验收。
- 跨模块改动记录接口需求与兼容影响；并行开发时协调文件归属，防止相互覆盖。仅保留当前工具链、共享运行组件与用户制作的内容。

## 首版验收样例

1. 机关图：通过连线组合拉杆、压力板和 AND 条件，实际控制门；修改连线确实改变运行结果。
2. 敌人图：用现有守卫制作四状态图，可编辑条件与优先级，并观察运行状态及回溯恢复。
3. 关卡图：配置房间完成事件，解锁中庭捷径，并写入独立测试存档；空间连接有对应入口出口。
4. 三类图均支持保存、关闭、重新打开，节点、参数、连线和场景绑定保持有效。
5. 整体样例可在同一世界内连续游玩；切换正式美术后，关键解法、碰撞和回溯仍有效。
