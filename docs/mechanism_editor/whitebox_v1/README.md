# 第一批机关素材与状态节点

更新：2026-11-16。机关显示名称使用纯名称，不带“白盒 ·”“示例 ·”等前缀。

## 素材

打开 GodotLevelEditor → 机关 → 我的机关，双击素材或点击“进入编辑”。可通过“另存为”制作自己的版本，再从关卡轮盘的机关分类放入场景。

| 名称 | 源场景 | 状态 |
|---|---|---|
| 按钮 | `scenes/mechanisms/button.tscn` | idle / pressed，默认 0.5 秒弹起 |
| 拉杆 | `scenes/mechanisms/toggle_switch.tscn` | off / on |
| 压力板 | `scenes/mechanisms/pressure_plate.tscn` | released / pressed，真实玩家或配重占位驱动 |
| 滑动门 | `scenes/mechanisms/sliding_door.tscn` | closed / opening / open / closing |
| 旋转门 | `scenes/mechanisms/hinged_door.tscn` | closed / opening / open / closing |
| 升降台 | `scenes/mechanisms/lift_platform.tscn` | at_start / moving / at_end / stopped |
| 交互终端 | `scenes/mechanisms/terminal.tscn` | offline / ready / activated，默认 ready |

每份素材都是可编辑的 Assembly 场景与同名 `.graph.tres`，包含真实网格、碰撞或检测区域。门与升降台的碰撞随动作移动；升降台可载着角色移动。旧拉杆、压力板、门及用户机关继续保留。

## 编辑状态和逻辑

选中组件节点，在右侧“组件状态配置”选择初始状态、允许交互、锁定或单次使用。自定义状态输入英文 ID，以逗号分隔并按 Enter 应用；再添加“原状态 → 动作 → 新状态”规则。动作 ID 使用 `interact` 可覆盖该状态下的玩家 F 交互。自定义规则不能直接跳入 opening / closing / moving 等动画过渡状态。

检测范围、压力板释放延迟、有效碰撞层、要求占位数量、动作时长、升降台目标偏移、门旋转角度等在原生检查器中配置。压力板状态由实际占位驱动，不允许图直接伪造“已踩下”。新压力板默认检测玩家层 2 和配重层 4。

机关图在原有 AND、OR、NOT、数值、上升沿和延迟基础上新增：

- 七种组件节点，用于创建、绑定对应三维组件。
- 检测机关当前状态。
- 交互成功、状态变化、进入／退出指定状态、动作完成、进入／离开感应区触发。
- 请求改变状态、请求执行动作、设置交互可用、设置受支持的属性。
- 条件分支。

节点的状态与动作从所选组件读取下拉选项。属性仅开放锁定、交互可用、动作时长和按钮复位时长。右侧“模拟交互”和“踩板”用于隔离预览，不改变真实场景的运行状态。

## 任务与常驻关卡逻辑

任务图和常驻关卡图共用以下机关节点：

| 节点 | 用法 |
|---|---|
| 机关状态变化时 | 可选原状态／新状态，留空表示任意 |
| 机关交互成功时 | 可限制为玩家，只接收成功交互 |
| 机关动作完成时 | 可按动作名称、成功／取消失败过滤 |
| 进入／离开机关感应区域时 | 可限制为玩家 |
| 检测机关当前状态 | 输出布尔值，接条件组合或分支 |
| 等待机关到达状态 | 启动时先检查当前状态；支持超时、取消和分支组 |
| 请求机关改变状态／执行动作 | 继续端口表示指令已接受，失败端口显示拒绝原因 |
| 设置机关交互可用／设置机关属性 | 控制可操作性与明确开放的属性 |

选择当前关卡中的“机关实例 / 组件”，再选状态或动作。一个组合内的按钮、门等可分别绑定，同一素材放置多次也分别识别。保存前检查缺失实例、失效状态和动作。

`请求门打开 → 等待门到达 open → 完成任务` 能避免提前判定。已经打开的门会立即通过等待；`opening` 期间不会被当作 `open`。状态保存和复位不重放交互、状态变化或任务完成事件。

## 试玩

打开 `scenes/levels/mechanism_whitebox_v1.tscn` 并按 F6：

1. 左侧：按下按钮，等待滑动门完全打开。
2. 中间：F 拿起配重箱，放在一个压力板上，玩家站到另一个压力板，旋转门打开；离开任意板会关门。
3. 右侧：激活终端，升降台移动到终点；角色可以站在平台上一起移动。

场景上的三项示例目标使用同一任务节点与运行器，模板图位于 `resources/mechanisms/whitebox_v1/`。它们不写入用户的事件工作簿，也不修改默认主入口。用于正式任务时，通过任务页编辑相应任务，并绑定自己关卡中的实例。

验证、截图和命令见 [验证记录](validation.md)。
